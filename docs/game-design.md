# 모스힐 길드 일지 — 게임 기획서 v0.1

> 30분 맛보기판(버티컬 슬라이스) 기준 설계.
> 엔진은 Ren'Py 8, 플랫폼은 PC, 언어는 한국어.
> 구조는 Summertime Saga 분석(`docs/summertime-saga-structure-analysis.md`)을 바탕으로 하고,
> 앞선 실험(`renpy-sprite-demo/`)에서 검증된 방식만 가져온다.
> 유효 에셋은 **루비(몸 1장 + 표정 6장)** 뿐이고, 나머지는 이 문서의 목록대로 새로 만든다.

---

## 1. 한 줄 소개

망하기 직전인 시골 모험가 길드를 물려받은 주인공이, 길드의 마지막 남은 멤버 **루비**와 함께
**3일 안에** 의뢰를 해결해 길드 면허를 지켜내는 코믹 판타지 RPG.

- **장르:** 마을 생활(비주얼노벨식 장소 이동·대화) + 파티 턴제 RPG
- **톤:** 가볍고 유머 있는 일상, 틈틈이 던전 모험
- **참고 구조:** Summertime Saga — 장소 트리, 시간대, 캐릭터별 퀘스트 상태 머신, 클릭형 오브젝트

## 2. 맛보기판 범위 (30분)

| 항목 | 수량 | 비고 |
|---|---|---|
| 플레이 기간 | 게임 내 3일 | 하루 4칸(아침/오후/저녁/밤) |
| 장소 | 9곳 + 마을 지도 | 길드하우스 3, 마을 4, 던전 2 |
| NPC | 4명 | 루비(동료) + 3명 |
| 파티 | 2명 | 주인공 + 루비 |
| 적 | 4종 | 일반 3 + 보스 1 |
| 퀘스트 | 메인 1줄기 + 서브 2개 | |
| 전투 | 약 5~6회 | 튜토리얼 1 + 던전 + 보스 |

**넣지 않는 것 (맛보기판 이후):** 마을 밖 월드맵, 동료 3명 이상, 제작·요리, 낚시 같은 미니게임, 여러 엔딩.

## 3. 이야기

### 배경
- **모스힐:** 숲과 이끼 동굴 옆의 작은 마을. 슬라임과 고블린이 조금 귀찮게 구는 평화로운 곳.
- **이끼발굽 길드:** 한때 잘나갔지만 지금은 멤버가 루비 한 명뿐인 모험가 길드. 낡은 2층 길드하우스를 쓴다.
- **사건:** 왕도 모험가 협회에서 "3일 뒤 감사, 실적이 없으면 면허 취소" 통지가 온다.

### 등장인물

| 이름 | 역할 | 성격 | 그림 |
|---|---|---|---|
| **주인공** (이름 입력, 기본 "카이") | 플레이어. 길드를 물려받은 초보 모험가 | 말수 적은 츳코미 담당 | 대화용 스프라이트 1종 + 표정 4 |
| **루비** | 첫 동료 겸 히로인. 길드 유일 멤버, 검사 | 밝고 의욕 넘치지만 덜렁댐 | **기존 에셋 사용** (몸 1 + 표정 6) |
| **마르타** | 선술집 '졸린 곰' 주인. 의뢰 게시판 관리 | 털털한 큰누나, 잔소리꾼 | 몸 1 + 표정 4 |
| **핍** | 잡화점 주인. 하프링 상인 | 수다쟁이, 돈 계산에 밝음 | 몸 1 + 표정 4 |
| **그레고르** | 협회 감사관. 3일차에 등장 | 깐깐하지만 공정함 | 몸 1 + 표정 3 |

### 3일 흐름

| 날 | 아침 | 오후 | 저녁 | 밤 |
|---|---|---|---|---|
| **1일차** | 도착, 루비와 만남 (튜토리얼) | 마을 둘러보기, 마르타에게 첫 의뢰 | 숲길 슬라임 퇴치 (전투 튜토리얼) | 길드에서 루비와 대화, 잠 |
| **2일차** | 핍의 의뢰: 동굴에서 잃어버린 짐 | 이끼 동굴 탐색 (고블린, 버섯) | 동굴 보스 '두꺼비 왕' | 귀환, 보상 |
| **3일차** | 감사관 그레고르 도착 | 실적 보고 (퀘스트 결과에 따라 대사 변화) | 면허 유지 축하 / 다음 이야기 예고 | 엔딩 |

- **서브 퀘스트 1 (루비):** 루비가 잃어버린 부싯돌 찾기 → 저녁 벽난로 대화로 신뢰도 상승. 앞 데모의 퀘스트를 정식으로 옮긴다.
- **서브 퀘스트 2 (마르타):** 선술집 지하 창고의 쥐(슬라임) 퇴치 → 보상으로 회복약.
- 서브를 했는지에 따라 3일차 감사 보고의 평가와 대사가 달라진다.

## 4. 장소 설계

### 장소 트리 (Summertime Saga 의 Location 트리 방식)

```
L_map (마을 지도)
├─ L_guild (길드하우스 앞)                         ← 지도 아이콘
│   ├─ L_guild_hall    길드 홀 (1층, 의뢰판·벽난로)
│   │   ├─ L_guild_kitchen  부엌
│   │   └─ L_guild_room     내 방 (2층)
├─ L_square (마을 광장)                             ← 지도 아이콘
├─ L_tavern (선술집 '졸린 곰')                      ← 지도 아이콘
├─ L_shop (핍의 잡화점)                             ← 지도 아이콘
└─ L_forest (숲길)                                  ← 지도 아이콘
    └─ L_cave_1 (이끼 동굴 입구) → L_cave_2 (두꺼비 왕의 방)
```

### 배경 목록

| ID | 장소 | 클릭할 물건 | 시간대 |
|---|---|---|---|
| `bg_guild_room` | 내 방 | 문, 침대(자기), 책상(일지·저장 안내) | 낮/밤 |
| `bg_guild_hall` | 길드 홀 | 계단, 현관문, 부엌 문, 의뢰판, 벽난로 | 낮/밤 |
| `bg_guild_kitchen` | 부엌 | 홀 문, 찬장(아이템), 화덕 | 낮/밤 |
| `bg_square` | 마을 광장 | 각 건물 입구, 우물, 게시판 | 낮/밤 |
| `bg_tavern` | 선술집 | 카운터(마르타), 의뢰 게시판, 지하 창고 문 | 낮/밤 |
| `bg_shop` | 잡화점 | 카운터(핍), 진열장(상점 열기) | 낮 (밤엔 닫힘) |
| `bg_forest` | 숲길 | 동굴 입구, 수풀(랜덤 조우) | 낮/밤 |
| `bg_cave_1` | 이끼 동굴 | 더 깊이, 상자, 출구 | 하나 |
| `bg_cave_2` | 두꺼비 왕의 방 | 보스 | 하나 |
| `map_town` | 마을 지도 | 장소 아이콘 5개 | 낮/밤 |

- 밤 배경은 낮 그림을 보정해서 만든다 (데모에서 검증됨). 단 **창문·촛불이 있는 곳**은 불빛 덧그림 조각 1장을 추가한다.
- 클릭할 물건은 배경에서 오려낸 조각 PNG (`tools/cut_objects.py` 방식).

### 진입 검사 (lock check) 규칙
- 잡화점은 밤에 닫힘.
- 숲길은 1일차 오후에 첫 의뢰를 받기 전까지 잠김.
- 동굴은 핍의 의뢰를 받기 전까지 잠김.
- 밤에는 마을 밖(숲, 동굴)에 나갈 수 없음.

## 5. 시스템 설계

### 5-1. 시간 (`core/time.rpy`)
- 하루 4칸. 행동 일부가 시간을 1칸 소모한다(의뢰 수행, 던전 진입, 쉬기).
- 밤에 잠자기 → 다음 날 아침. 이때 모든 캐릭터에 `T_all_sleep` 신호, 상점 재고 갱신, 파티 HP/MP 전부 회복.
- 3일차 오후가 되면 감사 이벤트가 강제로 시작된다.

### 5-2. 장소와 화면 (`core/location.rpy`)
- 데모의 `Location`, `MoveTo`, `global_lock_check` 구조를 그대로 쓴다.
- 장소 1곳 = screen 1개 + 진입 label 1개 + lock check 1개.
- 물건 버튼은 **데이터로 정의**한다 (if 사슬을 줄이기 위함):

```python
OBJECTS["guild_hall"] = [
    Obj("hall_stairs",  MoveTo("guild_room"), "2층 내 방"),
    Obj("hall_board",   Interact("guild_board"), "의뢰판"),
    Obj("hall_door",    MoveTo("map"), "밖으로", when=lambda: not story.is_state(S_intro)),
]
```

### 5-3. 퀘스트 (`core/quest.rpy`)
- 캐릭터마다 상태 머신(Machine) 하나. 상태 문장이 그대로 퀘스트 힌트가 된다.
- **세이브는 "발생한 트리거 목록"으로 저장**하고 불러올 때 다시 재생한다 (원작 방식). 업데이트로 퀘스트가 바뀌어도 세이브가 잘 깨지지 않는다.
- 위치표: 요일·시간대별로 NPC가 어디 있는지 정한다.

| NPC | 아침 | 오후 | 저녁 | 밤 |
|---|---|---|---|---|
| 루비 | 부엌 | 주인공과 동행 (파티) | 길드 홀 | — |
| 마르타 | 선술집 | 선술집 | 선술집 | 선술집 |
| 핍 | 잡화점 | 잡화점 | 광장 | — |

### 5-4. 신뢰도 (`core/bond.rpy`)
- 루비만 신뢰도 0~100 을 가진다. 대화 선택지, 선물, 서브 퀘스트, 전투 중 감싸주기로 오른다.
- 30 / 60 에서 대사와 전투 연계기(합동 스킬)가 열린다.
- 원작처럼 숫자보다 **퀘스트 단계가 관계의 뼈대**이고, 신뢰도는 그 위의 보너스.

### 5-5. 파티 턴제 전투 (`rpg/battle.rpy`)
- **화면:** 원작처럼 정적인 그림 + 코드 모션. 왼쪽에 파티, 오른쪽에 적 (최대 3마리).
- **턴 순서:** 속도(SPD) 순서. 한 라운드마다 다시 정렬.
- **행동:** 공격 / 스킬(MP 소모) / 아이템 / 방어(받는 피해 절반) / 도망(보스전 불가).
- **피해 공식 (초안):** `피해 = max(1, 공격력 × 위력 − 방어력 ÷ 2) × (0.9 ~ 1.1)`
- **상태 이상:** 맛보기판에서는 2개만 — 독(턴마다 피해), 기절(1턴 쉼).
- **연출:** 데모의 `attack_lunge`, `hit_flash`, `heal_glow`, 데미지 숫자, 화면 흔들기를 재사용한다.
- **계산은 순수 Python 클래스로** 화면과 분리한다 → 나중에 밸런스 테스트를 자동으로 돌릴 수 있다.

| 행동 흐름 |
|---|
| 조우 → `call battle("forest_slimes")` → 라운드 반복(행동 선택 screen → 계산 → 연출) → 승리 시 경험치·골드·아이템 → 레벨업 연출 → 원래 장소로 복귀. 패배 시 길드 침대에서 깨어남(골드 절반 손실). |

### 5-6. 스탯과 성장 (`rpg/stats.rpy`)
- 스탯: HP, MP, 공격(ATK), 방어(DEF), 속도(SPD). 레벨 1~5 (맛보기판).
- 레벨업마다 스탯이 고정 표만큼 오르고, 레벨 3 에서 스킬 1개씩 추가.

| 캐릭터 | 역할 | 시작 스킬 | Lv3 스킬 |
|---|---|---|---|
| 주인공 | 균형형, 보조 | 응급처치 (HP 회복) | 도발 (적의 공격을 끌어옴) |
| 루비 | 공격형 | 회전베기 (적 전체) | 불꽃베기 (부싯돌 퀘스트 완료 시) |

### 5-7. 인벤토리, 장비, 상점 (`rpg/inventory.rpy`)
- 아이템 종류: 소모품 / 장비(무기·방어구·장신구 1칸씩) / 퀘스트 아이템.
- 상점: 핍의 잡화점(사기·팔기). 재고는 아침마다 갱신.
- 맛보기판 아이템 약 12종 (회복약, 마나 물약, 해독초, 장비 6종, 퀘스트 아이템 3종).

### 5-8. 데이터 파일 (`game/data/`)
코드를 건드리지 않고 숫자와 내용을 고칠 수 있게 JSON 으로 뺀다.

```
data/items.json       아이템 (이름, 설명, 가격, 효과)
data/skills.json      스킬 (MP, 대상, 위력, 효과)
data/enemies.json     적 (스탯, 행동 패턴, 드롭)
data/encounters.json  조우표 (장소별 등장 적과 확률)
data/shops.json       상점 품목
data/levels.json      레벨업 표
```

### 5-9. 세이브
- Ren'Py 기본 세이브 + `save_version` 번호.
- 퀘스트는 트리거 기록 재생 방식 → 버전이 올라가도 이어서 플레이 가능.

## 6. 폴더 구조

```
mosshill/                         ← 새 Ren'Py 프로젝트 (앞 데모와 별개)
├─ game/
│  ├─ core/        time.rpy · location.rpy · quest.rpy · bond.rpy · save.rpy · actions.rpy
│  ├─ rpg/         stats.rpy · battle.rpy · battle_screens.rpy · inventory.rpy · shop.rpy
│  ├─ ui/          hud.rpy · menus.rpy · popup.rpy · styles.rpy
│  ├─ locations/<장소>/   screen.rpy · enter.rpy · lock.rpy
│  ├─ characters/<인물>/  sprite.rpy · quest.rpy · talk.rpy
│  ├─ story/       day1.rpy · day2.rpy · day3.rpy
│  ├─ data/        *.json
│  ├─ images/
│  │  ├─ characters/<인물>/   <인물>_body.png · <인물>_face_<표정>.png
│  │  ├─ bg/                  bg_<장소>_day.jpg · bg_<장소>_night.jpg
│  │  ├─ objects/             object_<장소>_<물건>_<day|night>.png
│  │  ├─ enemies/             enemy_<이름>.png · enemy_<이름>_hurt.png
│  │  ├─ items/               icon_<아이템>.png
│  │  └─ ui/
│  ├─ audio/       bgm_*.ogg · sfx_*.ogg · amb_*.ogg
│  └─ fonts/
├─ tools/          cut_objects.py · build_preview.py · balance_sim.py
└─ docs/           (이 문서와 대본)
```

**규칙**
- 캐릭터 1명 = 폴더 1개, 장소 1곳 = 폴더 1개 (원작 방식).
- label 이름은 `<장소 또는 인물>_<내용>` (예: `tavern_enter`, `ruby_talk_morning`).
- 화면에 보이는 모든 글자는 `story/` 와 `characters/*/talk.rpy` 에만 둔다 → 나중에 번역하기 쉽다.

## 7. 아트 가이드

### 화풍
- **기준 이미지:** 루비 (`ruby_body.png`). 새 그림은 항상 루비를 화풍 견본으로 같이 넣어 생성한다 (데모에서 검증됨).
- 특징: 얇고 진한 외곽선, 단순하게 정리된 형태, 부드러운 그라데이션 음영, 따뜻한 낮빛.

### 규격

| 종류 | 크기 | 규칙 |
|---|---|---|
| 배경 | 1280×720 JPG | 생성은 1536×1024 → 위아래 잘라 16:9 |
| 대화 스프라이트 | 480×720 투명 PNG | 3/4 측면, 허벅지에서 잘림, 화면 높이 가득. NPC는 왼쪽을, 주인공은 오른쪽을 바라봄 |
| 표정 | 몸과 같은 캔버스 | 얼굴 타원 영역만 다시 그림 (마스크 편집) |
| 적 | 최대 480×480 투명 PNG | 바닥 정렬 |
| 아이콘 | 64×64 PNG | |
| 오브젝트 조각 | 배경에서 자동으로 오려냄 | 낮/밤 두 장 |

### 생성 순서 (일관성 유지)
1. 길드 홀 배경을 먼저 만들어 **배경 화풍 기준**으로 삼는다.
2. 나머지 배경은 "루비 + 길드 홀"을 견본으로 넣고 생성한다.
3. NPC 는 루비를 견본으로 몸 1장 → 얼굴 마스크로 표정.
4. 적은 루비 + 배경 1장을 견본으로.

### 에셋 수량과 예상 비용

| 종류 | 장수 | 예상 비용 |

| **합계** | | **약 3달러 안팎** |

### 사운드

- 필요 목록: BGM 4 (마을 낮, 마을 밤, 던전, 전투) + 보스 1, 효과음 약 12, 환경음 3.

## 8. 제작 단계

각 단계가 끝나면 **실제로 플레이해 확인한 뒤** 다음으로 넘어간다.

| 단계 | 내용 | 그림 | 확인 방법 |
|---|---|---|---|
| **M0 뼈대** | 새 프로젝트, 폴더 구조, 폰트, 루비 옮기기, 데이터 파일 틀 | 루비만 | 프로젝트 실행 |
| **M1 마을 시스템** | 시간, 장소 트리, 지도, 진입 검사, 퀘스트 머신, HUD | 회색 임시 박스 | 3일 동안 장소 이동만으로 돌아다니기 |
| **M2 전투 시스템** | 파티 턴제, 스탯, 스킬, 아이템, 레벨업 + 밸런스 시뮬레이터 | 임시 실루엣 | 시뮬레이터로 전투 100판 자동 실행 |
| **M3 아트** | 7장 목록대로 생성 → 조각 오려내기 → 교체 | 전부 | 화면 전체 스크린샷 검수 |
| **M4 이야기** | 3일치 대본, 퀘스트 대사, 선택지 | — | 처음부터 끝까지 플레이 |
| **M5 다듬기** | 사운드, 연출, 밸런스 조정, 버그 수정 | — | 30분 완주 테스트 |

- 그림 생성(비용 발생)은 M3 에서 한 번에 한다. 그 전에는 임시 박스로 시스템을 끝까지 검증한다.
- 각 단계마다 브라우저 미리보기 페이지를 같이 만들어 바로 확인할 수 있게 한다.
